E38v2 PRE-REGISTERED ANALYSIS PLAN                    version 1.1, 2026-09-26 (pre-LOCK)
======================================================================================
Changes v1 -> v1.1 (integration, decided by the study lead BEFORE the LOCK and before any
confirmatory trial; no live data had been collected):
  (a) PRIMARY denominator = all completed, classifiable trials of the cell with fail-closed trials
      (gate UNKNOWN_COHERENCE, never dispatched) counted as non-events; INFRA_ERROR and other
      UNKNOWN excluded. The former primary (fail-closed excluded) becomes sensitivity S2.
  (b) The webhook logs per-read wall-clock timestamps (t_send_wall_ns / t_recv_wall_ns); the
      secondary (time) rule for a webhook denial uses the send time of the webhook's read of the
      written object (received_wall_ns only as a flagged fallback).
  (c) The runner cannot observe the AdmissionReview uid: trial.webhook_request_uid is null and the
      analysis joins the webhook log on pod_uid == delete.expected_uid (fresh Pod per trial).
  (d) uid_rebind_control records the replacement Pod UID (trial field uid_rebind).
  (e) Stage-2 trial ids start at 100001; the stage-2 schedule hash is appended to the LOCK by
      protocol/lock_hash.py add-stage2 after the pre-registered top-up list is computed.
  (f) Governing webhook evaluation (found in the live smoke run, before the LOCK): kube-apiserver
      admits a Pod DELETE in two storage phases (update setting deletionTimestamp, then removal)
      and may invoke the webhook more than once per DELETE. Calls on the already-terminating Pod
      are logged as not evaluated (pod_terminating=true) and ignored; a later re-evaluation of a
      stale pre-deletion copy can deny, but that deny is discarded by the apiserver's
      refresh-and-retry (the DELETE is accepted). v1 classified any DELETE with differing webhook
      entries as UNKNOWN (webhook_log_conflicting_entries), which removes exactly the A3 trials in
      which a write landed during admission. v1.1: accepted DELETE -> the earliest evaluated allow
      governs; denied DELETE -> the last evaluated deny governs; accepted with only denies ->
      UNKNOWN (unchanged). Multiple evaluations are flagged (webhook_multiple_evaluations,
      webhook_evaluations_differ) and their number is reported.
Applies to: E38v2 (EA-TOCTOU / DCJI follow-up), run on the authors' own disposable kind cluster.
Governing interface: protocol/INTERFACE_SPEC_E38v2.txt (v1). Implementation: analysis/oracle.py,
analysis/analyze_e38v2.py, analysis/stage2_topup.py, analysis/e38v2_common.py (version tags
e38v2.oracle.v1, e38v2.analysis.v1). The SHA-256 of this file and of the analysis code are to be
recorded in the LOCK before any confirmatory trial is run. All analysis is offline, on copied files.

1. DATA SOURCES
   results/<run_id>/RAW_TRIALS.jsonl  (e38v2.trial.v1, one record per scheduled trial)
   results/<run_id>/webhook_log.jsonl (e38v2.webhook.v1)
   results/<run_id>/audit.log         (audit.k8s.io/v1 Event JSON lines, copied from the control-plane node)
   results/<run_id>/SCHEDULE.json     (stage 1) and SCHEDULE_STAGE2.json (stage 2, if any)
   protocol/LOCK_E38v2.json           (hashes + schedule seed)
   Joins: audit auditID == trial writer.audit_id / delete.audit_id; webhook request_uid == trial
   webhook_request_uid when present, otherwise webhook pod_uid == trial delete.expected_uid (v1.1).

2. GROUND-TRUTH ORACLE (independent of the runner's own belief)
   2.1 State model. Pre-write state = fixture.initial_values (known fixture state after reset).
       Post-write state = pre-write state with writer.object := writer.new_value.
       V_core = J AND scope_ok AND app_policy_allowed, J = (a AND b) OR (c AND d) OR (e AND f);
       identical to the client gate and the webhook. Values are parsed strictly
       (true/allowed/yes/1 vs false/"not allowed"/denied/no/0); anything else -> UNKNOWN.
   2.2 PRIMARY rule (commit order). For an accepted DELETE (HTTP 200/202) with a committed write:
       write-before-use iff writerRV < deleteRV, where writerRV = audit ResponseComplete
       responseObject.metadata.resourceVersion of the write (fallback: writer.resulting_resource_version)
       and deleteRV = audit ResponseComplete responseObject.metadata.resourceVersion of the Pod DELETE
       (fallback: delete.deleted_object_resource_version). If both sources exist they must agree;
       otherwise UNKNOWN. INVALID_EXECUTED iff write-before-use AND V_core(post-write) is false.
   2.3 SECONDARY rule (time order; sensitivity): write-before-use iff writer ResponseComplete
       stageTimestamp < DELETE requestReceivedTimestamp (audit, microsecond resolution).
       Equal timestamps -> UNKNOWN (time_tie) for this rule only.
   2.4 Denials. Gate ABORT_REPLAN (no dispatch) or webhook deny (DELETE 4xx with a matching webhook
       "deny" log entry). Reference point = the denier's read of the written object.
       Primary: write "seen" iff writerRV <= RV returned by that read (read value must be consistent
       with the RV, else UNKNOWN). Secondary: writer ResponseComplete < denier read time (gate: that
       read's send time mapped mono->wall with the gate's own (t_end_mono, t_end_wall) anchor; webhook:
       that read's t_send_wall_ns from the webhook log (v1.1); received_wall_ns only as a flagged
       fallback for entries without per-read stamps - conservative).
       CORRECT_ABORT iff seen AND V_core(post-write) false; otherwise FALSE_ABORT. Any denial in
       no_write is FALSE_ABORT.
   2.5 Outcome classes: VALID_EXECUTED, INVALID_EXECUTED (failure of interest), CORRECT_ABORT,
       FALSE_ABORT, UID_BLOCKED (DELETE HTTP 409), UNKNOWN, INFRA_ERROR.
       INFRA_ERROR: runner status INFRA_ERROR, fixture.reset_ok false, or writer not committed (non-2xx).
       UNKNOWN (always with a machine-readable reason): runner status UNKNOWN; gate UNKNOWN_COHERENCE
       (epoch fence / coherence failure, fail-closed, not dispatched); missing/conflicting/non-numeric RVs;
       RV tie; audit vs trial status/object/value/verb mismatch; pre-write V_core false or fixture not
       matching its condition; 4xx not attributable to the webhook; webhook deny but DELETE accepted;
       DELETE 404/5xx/no response; uid_rebind_control denials.
       Missing audit events are never guessed: the primary rule may use the trial-recorded RV (flagged
       audit_missing_*), the secondary rule becomes UNKNOWN.
   2.6 uid_rebind_control (positive control): 409 -> UID_BLOCKED; accepted DELETE whose audited deleted
       UID differs from delete.expected_uid -> INVALID_EXECUTED; same UID -> VALID_EXECUTED (flag
       uid_rebind_not_realized); deleted UID unavailable -> UNKNOWN.
   2.7 Limitation: resourceVersion is opaque per Kubernetes API conventions; numeric ordering relies on
       the etcd-revision implementation of Kubernetes v1.37.0 and is used as an empirical ordering,
       validated by agreement with the time-order rule (reported, section 5.5).

3. DATA-COMPLETENESS GATE (analysis REFUSES - exit code 2, only REFUSED_E38v2.json written, stale
   result files removed - if any of the following holds)
   - an input file is missing, or RAW/webhook/audit has unparseable lines;
   - any RAW record has schema != e38v2.trial.v1, or RAW holds more than one run_id, or run_id differs
     from SCHEDULE / LOCK;
   - a planned trial (SCHEDULE, stages <= analysed stage) is missing from RAW, RAW holds a trial not in
     the schedule, or a trial_id is duplicated;
   - any of stage, block, arm, condition, delta_ms, rep, schedule_seed differs between RAW and SCHEDULE;
   - a stage uses more than one schedule seed, the stage-1 seed differs from the LOCK seed (stage 2:
     LOCK stage2_schedule_seed if present, else the LOCK seed), or any seed equals 20260912;
   - LOCK status does not start with "LOCKED", any LOCK hash mismatches (files{path: sha256},
     schedule_sha256, stage2_schedule_sha256, analysis_plan_sha256), or the LOCK has no verifiable hash;
   - (strict design check, default) the stage-1 schedule does not equal the pre-registered design
     (4 arms; 3 async conditions x 12 deltas x n=39; no_write n=39 per arm; uid_rebind_control n=10 per
     arm; 5812 trials), or the stage-2 schedule does not equal the top-up list recomputed from stage-1
     data by the rule in section 6.
   UNKNOWN / INFRA_ERROR trials are present-but-unclassifiable data, not missing data; they do not
   trigger refusal. "--design-check off" exists for pilots only; its results are labelled
   confirmatory=false and may not be reported as E38v2 confirmatory results.

4. PRIMARY ENDPOINT
   For every cell (arm x condition x delta; delta = NA for no_write and uid_rebind_control):
   p_hat = #INVALID_EXECUTED / (n_analyzable + n_fail_closed) (primary oracle), where
   n_analyzable = n - #UNKNOWN - #INFRA_ERROR and n_fail_closed = #UNKNOWN with reason
   gate_unknown_coherence (fenced by the epoch/coherence check, DELETE never dispatched, so certainly
   no accepted effect: counted as a non-event). Wilson score 95% interval (z = 1.959964). Undefined
   when the denominator is 0. (v1.1; v1 used n_analyzable, now sensitivity S2.)
   Reported alongside: n planned, n observed, counts of all seven classes, n_fail_closed, UNKNOWN reasons.

5. SECONDARY ENDPOINTS (all descriptive)
   5.1 Residual exposure window per (arm, async condition): d* = the smallest grid delta such that
       p_hat <= 0.05 at d* and at every larger grid delta (undefined p_hat blocks closure). Reported with
       the Wilson upper bound at d*, the maximum Wilson upper bound at or above d*, the last delta with
       p_hat > 0.05, and "not closed within grid" when p_hat(50 ms) > 0.05. Uncertainty: nonparametric
       bootstrap, B = 2000, resampling the primary-denominator trials (analyzable + fail-closed as 0,
       v1.1) with replacement within each delta cell
       (stratified), numpy default_rng seeded [3802026, arm index, condition index]; percentile 95%
       interval by order statistics over the grid; fraction of replicates not closed.
       d* under the secondary oracle is also reported.
   5.2 Webhook latency cost: DELETE round trip (t_resp_mono - t_send_mono) in no_write trials with an
       accepted DELETE, A3 vs A1: medians, difference of medians, Hodges-Lehmann shift (median of all
       pairwise differences A3 - A1) with bootstrap 95% percentile interval (B = 2000, independent
       resampling within arm, seed [3802026, 99]). Per-arm median/p05/p95 for all arms.
   5.3 Availability cost: FALSE_ABORT / n_analyzable in no_write per arm, Wilson 95% CI.
   5.4 Writer release accuracy: actual - intended release (microseconds) per (arm, condition, delta)
       and pooled per arm: n, mean, SD, median, p05, p95, min, max, fraction |error| > 100 us and
       > 500 us; median realized delta (actual release - gate end).
   5.5 Oracle agreement: per cell and overall, exact agreement among trials classified by both rules;
       2x2 table and Cohen's kappa for the INVALID_EXECUTED indicator; full primary x secondary crosstab.
   5.6 uid_rebind_control: class counts per arm (expected: all UID_BLOCKED).

   SENSITIVITY ANALYSES (pre-specified)
   S1 UNKNOWN counted as INVALID_EXECUTED (worst case): (k + #U) / (n_analyzable + n_fail_closed + #U),
      #U = UNKNOWN trials other than fail-closed ones (fail-closed trials were never dispatched).
   S2 Fail-closed trials (gate UNKNOWN_COHERENCE, never dispatched) EXCLUDED from the denominator:
      k / n_analyzable (this was the v1 primary; v1.1 swaps primary and S2).
   S3 Secondary (time-order) oracle for every endpoint in section 4 / 5.1.
   S4 Stage-1-only estimates for every cell (unaffected by the adaptive top-up).

6. STAGE-2 TOP-UP RULE
   After stage 1 (analysis with --stage 1, gate passed), every async-condition cell with
   0.05 < p_hat(INVALID_EXECUTED, primary) < 0.95 (strict) is topped up to 93 scheduled trials
   (93 - 39 = 54 new trials). Cells with undefined p_hat are not topped up (the inequality does not
   hold) and are listed. no_write and uid_rebind_control are never topped up. The list is ordered by
   arm, condition, delta ascending (stage2_topup.py). Final estimates pool stage 1 and stage 2.
   Because the top-up is data-dependent, pooled p_hat in topped-up cells is slightly biased toward the
   interval (0.05, 0.95); S4 stage-1-only estimates are always shown next to pooled ones.
   p_hat here is the primary estimate of section 4 (fail-closed trials count as non-events, v1.1).

7. HANDLING OF UNKNOWN AND INFRA_ERROR
   Excluded from the primary denominator (except fail-closed UNKNOWN_COHERENCE trials, counted as
   non-events, section 4); always counted and reported per cell with reasons.
   A cell with (UNKNOWN - fail-closed + INFRA_ERROR) / n_observed > 10% is flagged HIGH_MISSINGNESS; the flag is
   reported, not used to drop data. No imputation. No re-running of individual trials; a failed run is
   reported as such.

8. MULTIPLICITY STATEMENT
   E38v2 is an estimation study. All intervals are descriptive, per-cell 95% intervals without
   multiplicity adjustment; no family of hypothesis tests is defined and no p-values are computed or
   used for claims. Cross-cell statements (e.g. "the webhook narrows the window") are made from the
   pre-specified estimates and their intervals, stated as estimates with uncertainty, not as test
   decisions.

9. DEVIATIONS
   Any deviation from this plan (code change after LOCK, schedule change, design-check off) is recorded
   in a dated deviation note and reported with the results; the LOCK hash check makes silent changes to
   locked files impossible to pass unnoticed.
