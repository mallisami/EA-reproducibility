E40 PROTOCOL - replication of the E38v2/E39-A core measurement on a managed Kubernetes control plane (Azure AKS)
version 1.0, 2026-09-26, written BEFORE the cluster exists and before any E40 data exist
=====================================================================================================================
Purpose. Address the "single-host kind testbed" limitation of E38v2/E39: replicate the exposure-window measurement
(P(INVALID_EXECUTED) versus writer delay delta) for the client gate (A1), client gate + validating admission webhook (A3)
and commit-bound enforcement (A4d) on a real managed control plane (AKS, remote etcd/apiserver, real kubelet on a VM).
Defensive systems-security research by the paper's authors, on their own disposable cluster, in their own subscription.

3. DESIGN (single stage, no top-up)
   Arms: A1_dcji (DCJI client gate + UID precondition), A3_dcji_webhook (A1 + validating admission webhook, in-cluster,
   objectSelector label), A4d_commit_direct (Pod-annotation state; DELETE with {uid, resourceVersion} preconditions).
   Conditions: async_scope, async_evidence_last_literal (A4d stores the state as Pod annotations).
   Delta grid (ms): {0, 2, 5, 10, 20, 50, 100, 200}; n = 39 per arm x condition x delta cell (1872 trials).
   Controls: no_write n = 39 per arm (117), uid_rebind_control n = 10 per arm (30). Total 2019 trials.
   Target: Running-and-Ready Pod (registry.k8s.io/pause:3.10). Randomisation: E39 build_stage1 (39 blocks, every cell once
   per block, uid controls in blocks 0-9, shuffled within block with random.Random("<seed>|E39-A|stage1")).
   Schedule seed: 40926017 (fresh; not 20260912, 1772720255, 154080643, 424242, nor the E39 seed in LOCK_E39.json).
   Run id: a20260926 (namespace e40-a20260926); smoke run id smoke1 (namespace e40-smoke1).
   TIME BOX (pre-registered, because the cluster must be deleted within 3 h): the full run executes whole blocks in
   schedule order; before starting a block, the wrapper stops if (cluster age + projected block duration from the
   running mean) would exceed 2 h 40 min. If that happens, the analysis uses the completed blocks only (analysis
   schedule = the executed blocks, hashed and reported as a deviation); n per cell is then equal across cells.

4. ORACLE (pre-registered deviation from E38v2/E39: AKS exposes no kube-apiserver audit log file; paid Log Analytics
   diagnostic export is NOT enabled)
   PRIMARY: the unchanged E39 oracle (analysis/oracle_e39.py) with an EMPTY audit log, i.e. its pre-registered
   fallbacks: write revision = writer PATCH response resourceVersion (trial.writer.resulting_resource_version); action
   revision = DELETE response resourceVersion, else the pod-watch DELETED-event resourceVersion (pod_events.jsonl, as the
   E38v2 rerun plan v1.2 (i)); denials: gate read RVs (client), 409 precondition message from the DELETE response body;
   webhook decisions from webhook_log.jsonl (joined on pod uid).
   SECONDARY (E40-specific, client-side timestamps, all on one node clock): accepted DELETE -> write "before" iff the
   writer's response was received before the DELETE response (response-receipt order, the client analogue of the E39
   ResponseComplete rule); gate denial -> write seen iff writer response received before the gate read of that object was
   sent; rv_precondition 409 -> writer response before DELETE response; webhook deny -> writer response (wall = mono + the
   runner's wall-mono offset) before the webhook read send wall time. Overlap fraction (writer [send, recv] intersects
   DELETE [send, recv]) reported. Agreement primary vs secondary (% and kappa) reported.
   RV-ORDER VALIDATION (probe, before trials): 50 sequential PATCHes on one ConfigMap and 50 on one Pod: response RVs
   must be strictly increasing integers; a PATCH followed by a DELETE of the same Pod: DELETE RV > PATCH RV.
   Limitations stated: resourceVersion treated as a numeric etcd revision (true for AKS etcd3 storage; opaque by API
   contract); no server-side stageTimestamps; 409 attribution (kubelet vs writer) only via pod-watch events.

5. PROBES (inside the runner Pod, before any trial; results in PROBES_E40.json)
   P1 identities (SelfSubjectReview for responder/writer/reset/mirror = e40-system SAs), /version v1.36.x, endpoint used.
   P2 webhook deny/allow on a labelled target Pod (scope false -> 4xx deny with webhook log entry; valid -> 200 allow).
   P3 A4d: DELETE with stale RV -> 409 whose message names the resourceVersion precondition; with current RV -> 200.
   P4 target Pod Running and Ready at the gate (pod_ready record, Ready latency).
   P5 kubelet status-update rate on a Running target Pod over 60 s after Ready (pod watch MODIFIED events not caused by
      the experiment) = expected source of false 409s for A4d.
   P6 RV-order probe (section 4).

6. SMOKE AND QUALITY GATES (smoke = 1 replicate per cell: 48 async + 3 no_write + 3 uid_rebind = 54 trials, unlocked)
